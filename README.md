# WBS 報告内容アシスタント（医事会計システム更新）

医事会計システムの更新プロジェクトで、WBS のワークシートに書く報告内容の候補を出す、オフラインの Windows アプリです。

- 過去事例（報告内容が記載された実用WBS）を取り込んでおきます。
- トピック（例：「マスタ移行」「連携テスト」「診療報酬改定対応」）を入れると、ワークシートの各欄に書くべき報告内容の候補を、**日本語と英語**で表示します。
- アプリは **Excel ファイルに一切書き込みません**。表示した内容をコピーし、フォーマット（Excel）へ手で転記します。
- 外部通信は一切行いません（HTTP 通信・自動更新・テレメトリ・外部 AI API なし）。Excel がない PC でも動きます。

## 1. 使い方

最初に「3. フォーマット・ひな形登録」→「2. 過去事例管理」の順に登録し、そのあとは「1. トピック検索」を使います。

### 3. フォーマット・ひな形登録

- **フォーマット**タブ：報告内容を記載する WBS ワークシートの様式（.xlsx / .xlsm）を登録します。
  - **様式プロファイル**（対象シート・ヘッダー行・データ開始行・各列の意味）を、見出しから自動で推定します。
  - 欄の例：WBS番号、工程、作業項目、作業内容、報告内容、進捗状況、課題・懸念、対応方針、担当、予定日、実績日、備考。
  - 推定に自信がないとき（確信度が 0.7 未満、または候補が複数）は黄色の注意書きが出ます。右のプレビューでセルをクリックし、［この行をヘッダー行に］［この列の意味にする］などで指定して、［プロファイルを保存］を押します。
  - 各欄の**書式制約**を読み取って表示します：
    - 入力規則（プルダウンの許可値）
    - 結合セル
    - 列幅（文字数の目安に使う）
    - 日付・数値の表示形式
    - 数式の列
- **ひな形**タブ：すべての作業項目を網羅した大本の WBS を登録します。作業項目のマスタとして使います。
  - 登録すると、作業項目名が用語辞書に入ります（英語は空欄）。

### 2. 過去事例管理

- 実用WBSを画面上部にドラッグ＆ドロップするか、［ファイルを追加…］で取り込みます（複数可）。
  - 登録済みのフォーマットのプロファイルで、行ごと・欄ごとに文を保存します。
  - 見出しに「英語」「(EN)」などを含む列があれば、同じ欄の英訳（対訳）として取り込みます。
- 各行は、ひな形の作業項目に次の順で対応付けます。
  1. WBS 番号の一致（名称がかけ離れている場合は採用しません）
  2. 正規化した作業項目名の一致（照合確認で選んだ同義語を含む）
  3. 類似度：90 以上は自動で対応付けます。70〜90 は「4. 照合確認」で選びます。70 未満はひな形外の追加項目です。
- **同じファイルの二重取込**はファイルのハッシュで検出し、警告します。
- 事例を選ぶと、**案件属性**を入力できます：更新種別、病床規模、ベンダー、連携システム、実施年度、自由タグ（任意）。

### 4. 照合確認

類似度が中間帯の行について、対応するひな形の作業項目を選んで［選択を確定］を押します。選んだ結果は同義語辞書に保存し、次回以降は自動で対応付けます。

### 1. トピック検索（メイン画面）

1. 上部で**案件**を選びます（［新規案件…］で作成、［案件の属性…］で今回の案件の属性を入力）。
   - 転記の進捗・差し替えた値・編集した文は案件ごとに保存されます。次回の起動時も続きから再開できます。
2. **トピック**を入れて Enter か［検索（Ctrl+F）］を押します。入力中は、ひな形の作業項目名が候補として補完表示されます。
   - 形態素解析＋BM25 で全欄を全文検索し、作業項目名（または工程名）の類似度と合算して順位を付けます。
   - 「属性で重み付け」「属性で絞り込み」を選ぶと、今回の案件の属性に近い過去事例を重視します。
3. **左**に作業項目が、必要性つきで並びます。
   - 必要性は「必要／要検討／不要」です。過去事例に転記されていた割合（採用率）で判定します。初期値は、採用率 70% 以上なら必要、30% 未満なら不要です。
4. **中央**に欄ごとの記載例が、日本語（左）と英語（右）で並びます。
   - **推奨記載例**：過去事例の記載から、最も代表的な文を 1 つ選んだものです。出現頻度が高く、他の記載とよく似ている文を選びます。
   - **他の記載例**：最大 5 件です。事例名・年度付きで表示し、選ぶと推奨と入れ替わります。
   - **根拠**：参照した事例名です。ルールを適用した場合は、ルール名も表示します。
   - **制約**：プルダウンの許可値（コピー時に許可値へ変換）、文字数の目安（超えると警告）、日付形式、結合セル。
   - 文は直接編集できます。日本語を直すと英語も訳し直します。英語を直した場合は、そのまま使います。
   - ［定型文として保存］で、表示中の文を**自分の定型文**として保存し、次回以降の候補に含めます。
5. 記載例の日付・固有名・数値は `{{病院名}}` `{{日付}}` のような**プレースホルダー**で表示します。
   - 上部の「今回の案件の値」に入力すると、すべての記載例で一括して差し替わります。
6. **右**の「記載先のプレビュー」に、フォーマット上の記載先のセルをオレンジで表示します（表示専用）。
   - 該当する行が複数ある、または見つからない場合は、プレビューで任意のセルをクリックし、［このセルを記載先にする］を押します。指定はプロファイルに保存されます。
7. 右の「転記チェックリスト」で、転記した作業項目・欄に「転記済み」のチェックを付けます。

### コピー

日本語と英語は、それぞれ別にコピーします。コピーすると画面下部に「コピーしました（日本語・3欄）」のように表示します。

| 操作 | コピーする内容 |
|---|---|
| 欄の［日本語コピー］［英語コピー］ | その欄の文 |
| ［行コピー（日本語）］［行コピー（英語）］ | 選択中の作業項目の 1 行分（タブ区切り） |
| ［全件コピー（日本語）］［全件コピー（英語）］ | 検索結果の全作業項目（タブ区切り） |
| Ctrl+J／Ctrl+E | 入力中の欄があればその欄、なければ選択中の作業項目の 1 行分（日本語／英語） |

- 行コピーと全件コピーは、フォーマットの列順のタブ区切りです。Excel の行頭のセルに貼ると、1 行分が正しい列に入ります。
- 「コピー形式」は 2 つから選べます。
  - **列位置をそろえる**：数式の列・結合セルの一部の列を空欄で埋め、列の位置をそろえます。
  - **対象欄のみ**：欄だけを列順に並べます。
- セルの中の改行は、Excel の貼り付け規則に合わせて `"…"` で囲みます。

### 5. 条件ルール管理

| 種類 | 内容 | 例 |
|---|---|---|
| 必要性を設定する | 条件（今回の案件の属性）を満たせば、対象の作業項目を 必要／要検討／不要 として提示します | 連携システムに PACS を含む → 『PACS連携テスト』を必要 |
| 事例を優先する | 条件を満たせば、指定した属性の事例の重みを上げます（推奨記載例・検索の順位に効きます） | ベンダー名 ＝ 架空システムズ の事例を 2 倍 |

- ルールは保存できます。有効／無効を切り替えられ、優先順位（小さいほど優先）を付けられます。
- ルールは統計による判定より優先します。適用したルールは根拠に表示します。

### 6. 設定

| タブ | 内容 |
|---|---|
| 閾値・検索 | 必要・不要の採用率、照合の類似度、検索の重み、表示件数、推奨記載例の重み、属性の重み付け・絞り込み、属性の選択肢、候補を出す欄 |
| 用語辞書 | 日本語 → 英語。検索、英語が空欄の語だけの表示、CSV（日本語,英語）のインポート・エクスポート |
| 定型文テンプレート | 報告内容の日英対訳（例：`{x}を実施した。` → `{x} was carried out.`）、必要性の根拠の文、自分の定型文の一覧・削除 |
| プレースホルダー | 差し替える語の見つけ方（正規表現、または取得元：過去事例のベンダー名・人名）と英語名 |

**英訳はオフライン**で、次の優先順位で行います。

1. 過去事例の英語の列・自分の定型文の英文（同じ日本語の文の対訳）
2. 定型文の日英対訳テンプレート
3. 用語辞書の最長一致での置き換え

訳せない語は英文に【未翻訳: ○○】と表示し、画面上部に件数を警告します。用語辞書に英語を登録すると、次の検索から反映されます。

設定は `%LOCALAPPDATA%\ApprovalReport\config.json`（初期値は `resources\default_config.json`）、定型文は `text_templates.json`、ログは `logs\app.log` に保存します。**ログにはセルの内容を書きません**（件数・処理名・エラーの種類と場所のみ）。

## 2. 配布（管理者権限なし）と警告が出たときの対処

### 配布

1. `ApprovalReport.exe`（単一ファイル）を、利用者の PC の任意のフォルダ（デスクトップ、ドキュメント、共有フォルダなど）にコピーします。インストーラーはありません。
   - GitHub の Releases から直接ダウンロードすることもできます。
2. ダブルクリックで起動します。管理者権限は不要です。
   - データ・設定・ログは `%LOCALAPPDATA%\ApprovalReport\`（例：`C:\Users\<ユーザー名>\AppData\Local\ApprovalReport\`）に作られます。exe の置き場所が書き込めない場所でも動きます。
   - HKLM のレジストリや Program Files には書き込みません。
   - 単一 exe のため、起動時に一時フォルダ（`%TEMP%\_MEI…`）へ展開します。起動には数秒かかります。
   - 過去事例を取り込んだあとの最初の起動では、検索インデックス（形態素解析）を作るため、進捗バーが出ます。結果はキャッシュするので、2 回目以降は新しい行だけを解析します。
3. アンインストールは、exe と `%LOCALAPPDATA%\ApprovalReport\` フォルダを削除するだけです。

### Windows SmartScreen の警告が出たとき

署名のない exe のため、「Windows によって PC が保護されました」と表示されることがあります。

- 配布元が確かな場合は、［詳細情報］→［実行］で起動できます。
- 組織で SmartScreen の回避が禁止されている場合は、情報システム部門に次を伝えて許可を依頼してください。
  - ファイル名と SHA-256 ハッシュ（PowerShell で `Get-FileHash .\ApprovalReport.exe -Algorithm SHA256`）
  - 用途（オフラインで動作し、外部通信を行わない社内ツールであること）
- 恒久的には、組織のコード署名証明書で exe に署名するのが確実です（`signtool sign /fd SHA256 /a ApprovalReport.exe` など）。

### ウイルス対策ソフトに誤検知されたとき

PyInstaller で作った単一 exe は、起動時に自分自身を展開する動きのため、誤って検知されることがあります。

1. 検知された場合は、自分で除外設定をせず、情報システム部門に**除外申請**してください。申請時は、上記の SHA-256 ハッシュ、ファイルの配置場所、用途を伝えます。
2. 誤検知としてベンダーに報告する（各ウイルス対策ソフトの誤検知報告窓口）と、次の定義ファイルで解消されることがあります。
3. 社内で配布する場合は、ソースからビルドした exe（ハッシュを記録）を 1 か所に置き、そのハッシュを除外申請に使うと管理しやすくなります。

## 3. 開発環境（VS Code）

### 必要なもの

- Windows 11 64bit
- Python 3.12
- VS Code（Python 拡張機能）

### 環境構築

```bat
cd approval_report
rem uv を使う場合
uv python install 3.12
uv venv --seed --python 3.12 .venv
.venv\Scripts\python -m pip install -r requirements.txt
rem uv を使わない場合
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

VS Code では、コマンドパレットの「Python: Select Interpreter」で `.venv\Scripts\python.exe` を選びます。

### 実行

```bat
.venv\Scripts\python main.py
```

開発中のデータも `%LOCALAPPDATA%\ApprovalReport\` に保存されます。環境変数 `APPROVALREPORT_HOME` で保存先を変えられます。

### テスト

```bat
.venv\Scripts\python tests\make_fixtures.py     rem ダミーの Excel（tests\fixtures）を作り直す
.venv\Scripts\python -m pytest
```

テストは、架空の病院名・ベンダー名で作ったダミーデータ（ひな形・フォーマット・過去事例 3 件）を毎回作り直して使います。

| ファイル | 内容 |
|---|---|
| `tests/test_search.py` | トピック検索の順位付け（全文検索・作業項目名・工程名）、照合（WBS 番号・確認待ち・ひな形外・同義語辞書）、属性による絞り込み・重み付け、過去事例 50 件・各 1000 行で 1 秒以内 |
| `tests/test_suggestions.py` | 代表文の選定（頻度・中心性・優先ルールの重み・最大 5 件）、採用率と閾値判定、ユーザールールの優先（優先順位・無効・事例の優先）、プレースホルダーの抽出と差し替え、自分の定型文 |
| `tests/test_output.py` | 日英生成（対訳・テンプレート・用語辞書の優先順位）と未翻訳語の検出、タブ区切りコピーの列位置がフォーマットの列順と一致すること、書式制約の読み取り、記載先の指定の保存、**Excel ファイルを一切変更しないこと**（ハッシュ・更新日時が不変）、通信・Excel 保存のコードがないこと |

### ビルド

```bat
build.bat
```

pip install → pytest → PyInstaller（`build.spec`。単一 exe・ウィンドウアプリ）の順に実行し、`dist\ApprovalReport.exe` を作ります。Janome の辞書は exe に同梱しています。

### 自己診断

```bat
ApprovalReport.exe --selftest C:\temp\diag --fixtures <approval_report>\tests\fixtures
```

画面を自動で操作して、次を一通り行います。

1. フォーマット・ひな形の登録
2. 過去事例の取込
3. 照合確認
4. トピック検索
5. プレースホルダーの差し替え
6. 行コピー
7. Excel ファイルが変わっていないことの確認

結果は `selftest.json` と画面の画像として保存します。自己診断のデータは出力先の中に作るので、`%LOCALAPPDATA%\ApprovalReport\` は変わりません。

## 4. 設計概要

### モジュール構成

```
approval_report/
  main.py                 起動（ログ・例外の捕捉・自己診断）
  app/                    GUI（PySide6）
    main_window.py        6 つの画面のタブ、ショートカット、検索インデックスの作成（QThread・進捗バー）
    widgets.py            アプリの状態、QThread ワーカー、例外の日本語表示、プレビューグリッド、案件属性の入力欄
    pages/                search_page（トピック検索）・cases_page（過去事例管理）・format_page（フォーマット・ひな形登録）・
                          matching_page（照合確認）・rules_page（条件ルール管理）・settings_page（設定）
  core/                   GUI・Excel に依存しない処理
    tokenizer.py          Janome による形態素解析（検索用トークン・人名）
    search.py             BM25（rank-bm25）＋ rapidfuzz の検索
    representative.py     推奨記載例の選定（頻度＋中心性）
    judgment.py           採用率・閾値判定・ルール・案件属性による重み
    placeholders.py       プレースホルダーの抽出と差し替え
    translate.py          日本語 → 英語（対訳・定型文テンプレート・用語辞書）
    copytext.py           タブ区切りのコピー用テキスト（フォーマットの列順）
    advisor.py            上記をまとめて、トピックから作業項目ごとの結果を作る
    matching.py           ひな形の作業項目との照合
    workflow.py           登録・取込・照合の一連の処理
    db.py / models.py / config.py / paths.py / normalize.py
  excel_io/               Excel の読み込み（書き込みはしない）
    reader.py             openpyxl での読み込み（読み取り専用）
    profile.py            様式プロファイルの自動推定（英語の列を含む）
    inspect.py            フォーマットの書式制約・記載先のセル
    preview.py            プレビュー用のデータ
  resources/              初期設定・定型文テンプレート・用語辞書の初期値
  tests/                  pytest とダミーデータの生成
  build.spec / build.bat / requirements.txt
```

### データベース（SQLite：`%LOCALAPPDATA%\ApprovalReport\advisor.db`）

| テーブル | 内容 |
|---|---|
| `formats` | 登録した様式（ひな形・フォーマット）。様式プロファイル・書式制約は JSON |
| `master_items` | ひな形の作業項目 |
| `cases` | 過去事例（ハッシュ・案件属性） |
| `case_rows` | 過去事例の各行。欄ごとの日本語・英語の文と、作業項目への対応付け |
| `row_tokens` | 検索インデックスのキャッシュ（形態素解析の結果） |
| `synonyms` | 照合確認で選んだ対応付け |
| `rules` | 条件ルール |
| `projects` / `edits` / `checklist` | 案件（属性・プレースホルダーの値）、案件ごとに編集した文、転記チェック |
| `phrases` | 自分の定型文 |
| `glossary` | 用語辞書 |

登録したフォーマット・ひな形は `%LOCALAPPDATA%\ApprovalReport\formats\` にコピーして使います。元のファイルは開くだけで変更しません。

### 画面の流れ

```
3. フォーマット・ひな形登録 ─→ 2. 過去事例管理 ─→ 4. 照合確認 ─→ 1. トピック検索（毎回ここを使う）
   （プロファイル・書式制約）     （取込・属性）     （中間帯の選択）    左：作業項目／中央：日英の記載例とコピー／
                                                                       右：記載先のプレビュー・転記チェックリスト
5. 条件ルール管理・6. 設定 はいつでも
```

## 5. 前提と仮定

回答が得られなかった項目は【仮定】として次のように実装しました。設定で変えられるものは「6. 設定」または `config.json` で変更できます。
