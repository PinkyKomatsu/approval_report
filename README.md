# WBS 記載例アシスタント（医事会計システム更新）

過去事例（報告内容が記載された実用WBS）を参考に、トピックを入れると WBS の各欄の**記載例**を日本語・英語で出すツールです。

- 出てきた記載例をコピーして、Excel に貼るだけで使えます。
- アプリは **Excel ファイルに一切書き込みません**。
- 完全オフラインで、外部通信はしません。Excel がない PC でも動きます。

## 使い方（5 ステップ）

| # | やること | 画面 |
|---|---|---|
| ① | **過去事例を取り込む**：記載済みの実用WBS（.xlsx / .xlsm）を「過去事例」タブにドラッグ＆ドロップ（複数可）。取り込むと「記載例を探す」に戻ります | 過去事例 |
| ② | **トピックを入力する**：例「マスタ移行」「連携テスト」「診療報酬改定対応」。入力中は過去事例の作業項目名を補完表示。Enter で検索 | 記載例を探す（上） |
| ③ | **作業項目を選ぶ**：見つかった作業項目が左に並びます（記載のあった事例の数つき） | 記載例を探す（左） |
| ④ | **記載例を確認する**：欄ごとに日本語（左）と英語（右）の推奨記載例が出ます。必要なら「他の記載例」と入れ替えたり、直接直したりします。`{{日付}}` などは上の「今回の値」に入れると差し替わります | 記載例を探す（中央） |
| ⑤ | **コピーして Excel に貼る**：欄ごとの［日本語コピー］［英語コピー］、または［1行コピー］ | 記載例を探す |

①は最初の 1 回だけです（事例が増えたら追加します）。2 回目からは②〜⑤だけです。

### 記載例の出し方

- **検索**：形態素解析（Janome）＋BM25 で、作業項目名・工程・全欄の文から探します。作業項目名の似ている度合い（rapidfuzz）も合わせて順位を付けます。工程名でも探せます。
- **推奨記載例**：同じ作業項目の過去の記載から、最も代表的な文を 1 つ選びます。
  - 多くの事例で書かれていて、他の記載とも似ている文を選びます。
  - 日付・病院名・件数などが違うだけの記載は、同じ文とみなします。
- **他の記載例**：最大 5 件です。選ぶと推奨と入れ替わります。［推奨に戻す］で元に戻ります。
- **参考にした過去事例**：記載例ごとに、どの事例の記載かを表示します。
- **今回の値**：記載例の日付・病院名・担当者・件数・数値は、`{{日付}}` `{{病院名}}` のように表示します。上の入力欄に今回の値を入れると、すべての記載例で一度に差し替わります（入れた値は次回も残ります）。
- **英語**：オフラインで、次の順に訳します。
  1. 過去事例の英語の列（見出しに「英語」「(EN)」などを含む列）
  2. 定型文の日英対訳（`resources\text_templates.json`）
  3. 用語辞書
  
  訳せない語は【未翻訳: ○○】と表示します。「用語辞書（英訳）」タブで英語を登録すると、すぐ反映されます。
- **文字数の目安**：過去事例の記載の長さから出し、超えると警告します。

### コピー

| 操作 | コピーする内容 |
|---|---|
| ［日本語コピー］［英語コピー］ | その欄の文 |
| ［1行コピー（日本語）］［1行コピー（英語）］ | 選んだ作業項目の 1 行分。過去事例と同じ列順のタブ区切りで、Excel の行頭のセルに貼ると各欄が同じ列に入ります |
| Ctrl+J／Ctrl+E | 入力中の欄があればその欄、なければ 1 行分（日本語／英語） |
| Ctrl+F | トピックの入力欄へ |

コピーすると、画面下に「コピーしました（日本語・3欄）」のように表示します。

### 取り込める過去事例

- 列は見出しから自動で判別します。
  - **作業項目**の列（見出し例：作業項目・作業名・タスク名）が必要です。
  - 記載の欄の列（作業内容・報告内容・進捗状況・課題・懸念・対応方針・担当・予定日・実績日・備考）が 1 つ以上必要です。
- 記載のないファイル（ひな形・空のフォーマット）は取り込みません。同じファイルを二度取り込もうとすると警告します。
- 「過去事例」タブの「読み取った欄」で、どの列を何として読んだかを確認できます。
- 見出しの言い方が違う場合は、`%LOCALAPPDATA%\ApprovalReport\config.json` の `header_keywords` に追加できます（例：`{"header_keywords": {"report": ["今月の状況"]}}`）。

## 配布（管理者権限なし）と警告が出たときの対処

1. `ApprovalReport.exe`（単一ファイル。GitHub の Releases からもダウンロードできます）を任意のフォルダに置き、ダブルクリックで起動します。
   - インストール・管理者権限は不要です。
   - 起動時に一時フォルダへ展開するため、起動に数秒かかります。
2. データ・設定・ログは `%LOCALAPPDATA%\ApprovalReport\` に保存します。
   - HKLM のレジストリや Program Files には書き込みません。
   - ログにはセルの内容を書きません。
3. アンインストールは、exe と `%LOCALAPPDATA%\ApprovalReport\` を削除するだけです。

**SmartScreen の警告**：署名のない exe のため「Windows によって PC が保護されました」と出ることがあります。

- 配布元が確かなら、［詳細情報］→［実行］で起動できます。
- 組織で禁止されている場合は、情報システム部門に次を伝えて許可を依頼してください。
  - ファイル名と SHA-256（`Get-FileHash .\ApprovalReport.exe -Algorithm SHA256`）
  - 用途（オフラインで外部通信をしない社内ツールであること）
- 恒久的には、組織のコード署名証明書で署名するのが確実です。

**ウイルス対策ソフトの誤検知**：PyInstaller の単一 exe は、起動時に自分自身を展開するため、誤検知されることがあります。

- 自分で除外設定をせず、情報システム部門に除外申請してください（SHA-256・配置場所・用途を伝えます）。
- ベンダーの誤検知報告窓口に報告すると、次の定義ファイルで解消されることがあります。

## 開発（VS Code）

```bat
cd approval_report
py -3.12 -m venv .venv                         rem または uv venv --seed --python 3.12 .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py                   rem 実行
.venv\Scripts\python -m pytest                 rem テスト
build.bat                                      rem pip install → pytest → PyInstaller（dist\ApprovalReport.exe）
```

- VS Code では「Python: Select Interpreter」で `.venv\Scripts\python.exe` を選びます。
- 環境変数 `APPROVALREPORT_HOME` で、データの保存先を変えられます。

### 構成

```
main.py                 起動（ログ・例外の捕捉・自己診断 --selftest）
app/                    画面（PySide6）：記載例を探す・過去事例・用語辞書
core/                   tokenizer（Janome）・search（BM25＋rapidfuzz）・representative（推奨記載例の選定）・
                        placeholders（今回の値の差し替え）・translate（英訳）・copytext（タブ区切り）・advisor（まとめ）・
                        workflow（取込）・db（SQLite）
excel_io/               reader（openpyxl。読み取り専用）・profile（見出しから列を判別）
resources/              初期設定・定型文の日英対訳・用語辞書の初期値
tests/                  pytest とダミーデータ（架空の病院名だけを使う）の生成
```

データベース（`%LOCALAPPDATA%\ApprovalReport\examples.db`）には、次の 4 つのテーブルがあります。

| テーブル | 内容 |
|---|---|
| `cases` | 過去事例 |
| `case_rows` | 各行の欄ごとの日本語・英語の文 |
| `row_tokens` | 検索インデックスのキャッシュ |
| `glossary` | 用語辞書 |

### テスト（`tests/test_examples.py`）

- 取込：列の判別（英語の列を含む）、ひな形・二重取込の扱い
- トピック検索：順位（全文・作業項目名・工程名）、過去事例 50 件・各 1000 行で 1 秒以内
- 代表文の選定、プレースホルダーの抽出と差し替え
- 日英生成と未翻訳語の検出
- 1 行コピーの列位置が過去事例の列順と一致すること
- **Excel ファイルを一切変更しないこと**（ハッシュ・更新日時が不変）、通信・Excel 保存のコードがないこと

### 自己診断

```bat
ApprovalReport.exe --selftest C:\temp\diag --fixtures <approval_report>\tests\fixtures
```

画面を自動で操作して、取込 → 検索 → 作業項目の選択 → 今回の値の差し替え → コピー を一通り行います。結果は `selftest.json` と画面の画像として保存します。

## 前提と仮定

| 項目 | 内容 |
|---|---|
| ひな形 | 使いません。作業項目は、過去事例の作業項目名（表記が同じもの）でまとめます |
| 記載例の単位 | 1 つのセルの文全体を 1 件として扱います（文に分割しません） |
| 代表的な文 | 出現頻度 0.6 ＋ 他の記載との類似度 0.4 の点数が最も高い文（`config.json` の `representative`） |
| 検索の順位 | 0.7 × BM25 ＋ 0.5 × 作業項目名の類似度（`config.json` の `search`） |
| 今回の値 | 日付・病院名・担当者（さん・様の付いた人名）・件数・数値を規則で見つけます（`config.json` の `placeholders`） |
| 1 行コピーの列順 | 最後に取り込んだ過去事例の列順 |
| 英訳の品質 | 規則による訳のため、語順は日本語に近くなります。よく使う語は用語辞書に登録すると改善します |
| 以前の版のデータ | 引き継ぎません（V2.0.0 までのフォーマット・ひな形・ルール・案件の機能は削除しました） |
